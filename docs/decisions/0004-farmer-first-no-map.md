# ADR 0004: 農家向け画面から地図登録を外す

- 状態: Accepted
- 決定日: 2026-09-04

## 決定

- 通常の田んぼ登録では、地図、筆ポリゴン、緯度経度、観測地点を入力させない。
- 登録項目は、田んぼの名前、大きさ（小・中・大）、品種、作付け日、出穂日とする。
- 作付け日と出穂日は必須とし、出穂日から日平均気温を積算する。
- 位置を持たないMVPの田んぼは、久井町向けの代表観測地点として世羅AMeDAS（地点番号 `67316`）をDB側で自動設定する。
- ホームは不規則な地図風ブロックではなく、同じ幅の大きなカードを縦に並べる。刈りどき、刈り遅れ、もうすぐ、刈りどき前、未設定、収穫済の順に表示する。
- 大きさはカードの面積では表現せず、「小」「中」「大」の文字で明示する。カード全体の色と状態名を併記し、色だけに依存しない。
- 画面上の利用者向け文言は日本語にする。技術用語、観測所選択、データ品質の詳細は通常操作から隠す。
- 既存の地図、PostGIS、筆ポリゴン取込基盤は互換性と検証履歴のため残すが、通常導線には出さない。

## 理由

農家による試用で、地図上の筆ポリゴンと実際の田んぼが一致しない例が多く、区画の選択や手描きも負担が大きいことが分かった。MVPの価値は正確な圃場形状を作ることではなく、「出穂日を登録した後は自動で積算され、次に刈る田んぼが短時間で分かる」ことにある。

カードの大きさを小・中・大で変えると、面積の大きな田んぼほど重要に見え、刈りどきの優先順位が弱くなる。同じ幅で緊急度順に並べ、文字と色を併用する方が、屋外のスマートフォンでも迷いにくい。

## データと互換性

- `fields.size_class`へ `SMALL`、`MEDIUM`、`LARGE`を保存する。
- 新規の簡易登録は `fields.geom` と `fields.area_m2` を空にする。
- 旧データの形状と面積は削除しない。既存画面用RPCも後方互換のため維持する。
- 作付け日は `crop_seasons.planting_date`、積算開始日は既存どおり出穂日スナップショットへ保存する。
- 田んぼ一覧と詳細は、形状を返さない所有者限定RPCを使用する。

## 制約

- 世羅地点の気温は久井町全域の各田んぼの微気象を表すものではない。MVPでは操作の簡単さを優先した代表値であり、収穫判断は現地確認と併用する。
- 5品種の公的な刈取適期積算温度は未確認のため、推測値を登録しない。公式または利用者設定の根拠あるルールがない田んぼは「基準未設定」と表示する。
- 将来、参加農家から位置入力の明確な需要と信頼できる区画データが得られた場合だけ、任意の高度機能として再検討する。
