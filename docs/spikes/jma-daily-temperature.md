# JMA日平均気温取得スパイク

- 状態: 観測所マスター検証済み（取得経路は未確定）
- 確認日: 2026-09-03
- 対象: 広島県三原市久井町

## 確認できたこと

1. 気象庁の「過去の気象データ・ダウンロード」から日平均気温と品質情報をCSVで取得できる。
2. アメダスの日ごとの値は概ね毎日1時頃までに更新される。公表後に値が修正される場合がある。
3. 一度に取得できるデータ量には上限があり、自動化ツールによる過度のアクセスを避けるよう明記されている。
4. 気象庁「地域気象観測所一覧」（2026年3月24日現在）p.42の広島県行で、世羅（地点番号67316、標高350m）と本郷（67386、標高331m）を確認した。両地点とも気温を観測する。世羅は緯度34°35.0′・経度133°03.0′、本郷は緯度34°26.1′・経度132°55.1′で、EPSG:4326へは度 + 0.1分 / 60で変換する。
5. JMAの日平均気温CSVには品質情報を含められるため、値と品質コードを分離して保存できる。

## 観測所マスター登録

`20260903040000_regional_weather_masters.sql` は上記PDFの地点番号を
`weather_locations`へ `(provider, external_id)` で冪等UPSERTする。登録値は次のとおり。

| 地点番号 | `weather_locations.location` (lon, lat) | 標高 | 観測要素（PDFの種類・備考） |
|---|---|---:|---|
| `67316` 世羅 | `(133.05, 34.5833333333)` | 350m | 四・降水量、気温、風向、風速、相対湿度 |
| `67386` 本郷 | `(132.9183333333, 34.435)` | 331m | 官・降水量、気温、風向、風速（日照・湿度・気圧を除く） |

PostGISの点を唯一の正本とし、Edge Function等が利用する `latitude`・`longitude`
は `ST_Y(location)`・`ST_X(location)` のstored generated columnで公開するため、座標の二重管理をしない。
圃場所有者向け `find_nearest_weather_locations(field_id, limit)` は圃場の代表点を
サーバー側で求め、気象地点を距離（m）昇順で返す。他アカウントの圃場は0行、未認証は拒否する。

## MVP実装方針

- `WeatherProvider`の背後へJMA固有のURL・パラメータ・CSV解析を閉じ込める。
- 06:30 JSTに前日分と未取得期間を地点単位で取得する。
- 12:30 JSTに失敗地点のみ再試行する。
- 週1回、直近60日を再取得して訂正値をUPSERTする。
- 同じ地点・日付は一意とし、取得結果と実行履歴を別テーブルへ記録する。
- 欠測を0℃に変換しない。品質情報が空の場合は取得失敗と観測値なしを区別する。
- 指数バックオフ、地点単位ロック、低い同時実行数を使う。

## 未確定・リリース前ゲート

「過去の気象データ・ダウンロード」は人向けUIであり、安定した公開APIとしての保証は確認できていない。非公開・内部エンドポイントの直接利用を本番仕様として固定しない。次の順で確定する。

1. 保存済みfixtureでProviderと積算処理を完成させる。
2. 1地点・短期間だけを使い、実際の取得手順、品質コード、負荷制限を検証する。
3. 自動取得の運用可否を気象庁の公開条件に照らして確認する。
4. 安定運用できない場合は、手動CSV取込をMVPの安全な代替経路とし、WAGRI等へProviderを差し替える。
